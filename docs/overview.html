DSLX

v2.2-1

A module that gives Lua the ability to write XML-like syntax that compiles to pure Lua — similar to JSX in JavaScript.

Start with the quick start Try it in the playground

Experimental. APIs may change without notice.

Quick start

1. Install

luarocks install daviluaxml

Requires Lua 5.5 and LPeg (installed automatically).

2. Create a .dslx file

-- hello.dslx
local function greet(el)
    return "Hello, " .. el.props.name .. "!"
end

return <greet name="world"/>

3. Run it via require

-- main.lua
package.path = package.path .. ";./?.dslx"
local dslx = require("dslx")   -- installs the .dslx searcher automatically
print((require("hello")))       -- Hello, world!

Or compile directly without touching require:

local compile = require("dslx.compile")
compile({ input = "hello.dslx", run = true })

Try these examples in the playground

How it works

In a .dslx file, any function defined in the Lua environment can be called in XML format. The tag becomes a function call that receives a single table with the tag name, the props and the childrens:

-- code in dslx
local function soma(element)
    local soma = 0
    for _, valor in ipairs(element.childrens) do
        soma = soma + valor
    end
    return soma + element.props.t
end

local pt = function(element) print(table.unpack(element.childrens)) end

<pt>
    <soma t={9}>
        {1}{2}{3}
    </soma>
</pt>

Becomes:

-- generated Lua
local function soma(element)
    local soma = 0
    for _, valor in ipairs(element.childrens) do
        soma = soma + valor
    end
    return soma + element.props.t
end

local pt = function(element) print(table.unpack(element.childrens)) end

pt{name="pt", props={}, childrens={soma{name="soma", props={t=9}, childrens={1, 2, 3}, node_type="full_element"}}, node_type="full_element"}

The pipeline:

flowchart LR A([".dslx"]) -->|source code| B["parser\n(LPeg)"] B -->|AST| C["runtime\nmake_new_code"] C -->|pure Lua| D(["load & execute"])

Syntax

Props

Props accept strings, Lua expressions (in {}), and booleans (name only):

<card titulo="olá" largura={10} destaque>...</card>

-- inside the handler:
el.props.titulo   -- "olá"   (string)
el.props.largura  -- 10      (Lua expression)
el.props.destaque -- true    (boolean — prop name only)

Childrens

Children can be literal text, Lua expressions, or nested elements:

<card>
    texto {40 + 2}
    <card/>
</card>

-- inside the handler:
el.childrens[1]  -- "texto "  (literal text)
el.childrens[2]  -- 42        (Lua expression)
el.childrens[3]  -- table     (nested element, result of <card/>)

A nested element runs before its parent (Lua evaluates table values before the constructor). If the nested element returns nil, the child simply doesn't exist in the childrens table.

Self-closing vs full tag

-- self-closing
local c = <card titulo="hi"/>

-- full
local c = <card titulo="hi">
    some text
</card>

AST node fields

FieldTypeDescription

self_closeboolean?true for self-closing tags only

Modules

DSLX is split into focused modules. Each module can be required individually.

dslx.parser
Parses DSLX source into an AST using LPeg. Extensible with custom patterns.
dslx.runtime
Generates Lua source from an AST and optionally executes it. Customizable handlers per node type.
dslx.compile
High-level API: compiles a .dslx file or string to Lua, write to disk, or run inline.
dslx.import
Hooks into Lua's require() system so .dslx files are loaded transparently.

is_element

is_element(fn: function) → boolean, string?, number?

Global installed by require("dslx"). Validates whether a function is a valid DSLX element handler: it must accept exactly 1 parameter (the element table).

Returns
true — function is valid.
false, error_message, nparams — function is invalid.
local dslx = require("dslx")

local function card(el) return el.props.title end
local function bad()   return "no args" end

print(is_element(card))  -- true
print(is_element(bad))   -- false   "..."   0
print(is_element(42))    -- false   "o elemento precisa ser uma função."

What DSLX is not

  • Not HTML — HTML is a web language for pages. DSLX is Lua+XML, where XML is a rigid system-level structuring language, not a UI markup language.
  • Not a Lua replacement — DSLX works alongside Lua. All .dslx code becomes pure Lua before execution; there's no separate runtime or VM.
  • Not a template engine — DSLX doesn't generate strings or HTML output. The XML syntax maps directly to Lua function calls.
